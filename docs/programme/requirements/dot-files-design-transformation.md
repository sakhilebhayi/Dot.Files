# DOT.FILES — PREMIUM DESIGN TRANSFORMATION, DOCUMENT EXPERIENCE & SECURE ECOSYSTEM SHARING

Mission: evolve Dot.Files into one of the most visually impressive, intuitive and enjoyable platforms in the Dot ecosystem, using all relevant installed design/UX/copy/motion skills. Not a routine refresh: a premium business file experience — an extension of a company's professional identity: sophisticated, organised, beautiful, trustworthy, effortless — while remaining a fully functional enterprise platform with secure tenant isolation, reliable previews and controlled sharing. Design inspires confidence; functionality earns trust.

1. Understand the ecosystem's visual identity first: inspect InfoDot, Dot.Files, Dot.Docs, Dot.Analytics, Dot.Mines, Dot.Central and other platforms (typography, colour, spacing, layout, navigation, components, animation, transitions, scroll, interaction, hierarchy, content, micro-interactions). Dot.Files must feel unmistakably part of the ecosystem with its own personality; never copy another platform's interface; the identity communicates professional document management, organisation, security, control.

2. Use all relevant installed skills (premium SaaS design, UI/UX, design systems, typography, copywriting, UX writing, content hierarchy, scroll animation, motion, interaction, responsive, accessibility, product storytelling, conversion design); Laravel Boost; apply guidance in the implementation, not a report; avoid generic AI dashboard aesthetics.

3. Redesign the COMPLETE experience (not one screen): premium digital workspace. Inspiration (never reproduce): Apple detail/simplicity, Linear precision, Dropbox file experience, Notion organisation, modern enterprise DMS, premium editorial sites. Principles: beautiful typography, sophisticated spacing, clear hierarchy, elegant file/folder presentation, smooth transitions, subtle motion, high-quality previews, contrast/readability, minimal clutter, consistent interactions, responsive, fast perceived performance. Avoid: excessive cards, gradients, oversized headings, purposeless decoration, generic templates, excessive borders/shadows, unnecessary animation, empty unfinished-feeling sections.

4. Beautiful document snapshots and previews — a defining feature. Businesses see their organised digital library, not anonymous filenames in a table. Where supported: PDF (first page thumb, title, type, metadata, preview action), Word (safe first-page representation), Excel (safe limited snapshot, never a full workbook via unauthorised thumbnail), PowerPoint (first/representative slide), images (HQ thumbnails + larger preview). Pipeline: async where necessary, secure storage, optimised sizes, regeneration, graceful unsupported handling, tenant isolation, SAME permissions as originals, no leaks via public thumbnail URLs, no active content execution, safe rendering/sandboxing. Visual browsing: grid with snapshots, information-dense list, folder previews, recents (accessed/modified), favourites, categories, grouped-by-platform; view switch preserves search/filter context.

5. Business-centric workspace: each business immediately recognises its environment — identity/logo/name, storage usage, totals, recent additions/modifications, shared-with-business, per-platform files, recent activity — ALL REAL tenant data, nothing fabricated. An organised business environment, not an admin panel.

6. Seamless secure ecosystem sharing (core capability): share files/folders with authorised users and platforms without download/re-upload; Dot.Files stays authoritative for permissions, approvals, activity (examples: Finance→Analytics user, contract→HR workflow, project doc→Projects, Mines report→Central, Docs→business folder, Emall invoice→Finance). Secure references and controlled permissions, never unrestricted URLs. Workflow: select → Share → identify business/owner/permissions → choose destination platform/user/business → authority check → owner/admin approval where required → review → approve/reject → grant specific access → destination gets secure reference → record + notify. Simple, with clear explanations.

7. OWNER APPROVAL AUTHORITY (non-negotiable): the owner controls confidential-document sharing. Capabilities: approve/reject requests, revoke, set expiry, define permitted actions, restrict downloads where enforceable, per-file and per-folder approvals, history, platform-access visibility, pending queue. Policies: approval for all external sharing; selected internal platforms for approved folders; approval for confidential documents; role-scoped approval; auto-expiry; predefined trusted workflows only when owner-authorised. Distinguish business ownership / platform access / user access / sharing approval. A platform never gets blanket library access for being part of the ecosystem. Approval centre: pending/approved/rejected/expired/revoked + recent activity; each request shows file/folder, requester, source/destination, reason, permission level, duration, date; simple approve/reject with confirmation for sensitive operations.

8. Seamless without compromising security: secure references, server-side checks, short-lived tokens/signed URLs, revocation, expiry, audit, secure platform auth, tenant-aware authorisation, idempotency, reliable notifications. Opening a shared file from another platform goes through the authorised integration; no physical duplication unless copy requested. SHARE grants access in place; MOVE changes location/association; COPY creates a managed instance — never interchangeable; revoking removes permission without deleting the original.

9. Exceptional preview/share interactions: selection reveals useful actions; preview shows title, metadata, content, versions, activity, sharing status, actions; share UI shows who/which platforms have access, approval requirement, active permissions, expiry; approvals quick and legible with subtle status indicators; no confusing multi-step flows.

10. Scroll motion and interaction: purposeful movement (page transitions, subtle reveals, folder navigation, preview transitions, selection states, upload progress, drag-drop feedback, hover, approval confirmations, animated storage indicators); sparing in frequent workflows; no heavy effects; reduced-motion respected; no layout shifts; responsive; mobile-capable; keyboard accessible; meaning without animation. Fluid, not theatrical.

11. Copy and storytelling: confident, clear, human ("Your Business Files" not "File Management Dashboard"; "Move to another Dot platform"; "Your storage overview"; "Who can access this file?"); clear sensitive-action explanations (sharing confirmation, approval notification, revocation wording as given); never AI-sounding.

12. Security and tenant isolation intact: preserve/verify isolation, ownership, roles, platform scopes, secure storage, private previews, references, audit, approval history, revocation, expiry, temp URLs, job isolation. No cross-business visibility of files/snapshots/metadata/search/requests. Owner approval enforced server-side (hiding UI is insufficient). Test two businesses, multiple users; cross-tenant impossible without authorised processes.

13. Stages: 1 design/experience audit; 2 design system + core interface; 3 snapshots/previews (secure thumbs, grid/list, access control); 4 sharing + approval (requests, owner approval, permissions, expiry/revocation, secure references, notifications, audit); 5 motion + copy + states; 6 testing and production verification (previews, sharing, approvals, revocation, platform access, isolation, performance; deploy via pipeline; verify production).

14. Done when: distinctive premium identity aligned to the ecosystem; COMPLETE interface redesigned; skills applied; visual snapshot browsing; previews for supported formats respecting permissions; secure cross-platform sharing with correct approvals; owner authority retained; least-privilege platform grants; all activity recorded; isolation intact; responsive; purposeful accessible animation; every visible interaction works; automated tests + production verification.

15. Vision: businesses open Dot.Files and think "this is how we want our business to operate — organised, professional, connected, in control." Documents visible, recognisable, navigable; available across the ecosystem without manual copies; the owner always knows and controls access. Beautiful on the surface, intelligent underneath, secure by design, connected across Dot. Implement the actual experience; preserve working functionality; test real workflows; verify. The standard of how a modern business manages its digital world.
