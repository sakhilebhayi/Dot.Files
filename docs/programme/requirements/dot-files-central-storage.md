# DOT.FILES — ENTERPRISE FILE MANAGEMENT, CENTRAL BUSINESS STORAGE & ECOSYSTEM INTEGRATION MASTER PROMPT

## Mission
Transform Dot.Files into the central file management and document storage platform for the entire Dot ecosystem: the secure digital filing system for every business registered through InfoDot. Every business has its own secure digital workspace; every Dot platform can work with that workspace; Dot.Files manages the files, controls their movement, enforces their security and maintains a complete record of what happens to them. Not another cloud-storage interface: an intelligent, enterprise-grade file infrastructure. Priorities in order: 1 security and tenant isolation; 2 data ownership and access control; 3 reliable file/folder management; 4 cross-platform movement and integration; 5 auditability; 6 performance/scalability/reliability; 7 exceptional design and UX. Never compromise security for convenience or aesthetics.

## 1. Understand the existing architecture first
Comprehensive audit before any change (use Laravel Boost): application architecture; database structure; file/folder models; storage implementation; upload/download; permissions and policies; tenant/company identification; authentication and InfoDot SSO; API endpoints; jobs/queues; previews; audit logs; existing integrations; deployment; tests/CI. Inspect how the OTHER platforms actually create/store/retrieve/reference files — do not assume one architecture. Establish an integration contract that lets each platform use Dot.Files without unnecessary rewrites. Preserve working functionality, migrate existing files safely, never create a second competing storage architecture.

## 2. Central storage layer
All Dot platforms (Analytics, Pulse, Plug, Mines, Notify, Billing, Charts, Farms, HR, Memory, Brain, Dopemine, Emall, Ehail, Agents, Auction, Central, Projects, Tasks, Design, Finance, Docs, InfoDot) should be able to integrate — verify the ACTUAL deployed inventory first. Principle: a platform stores a file in Dot.Files and retains a secure reference (HR: employee documents; Finance: invoices/statements; Billing: receipts; Mines: production/equipment records; Docs: user documents; Projects: project files; Analytics: report exports; Agents: approved generated documents; InfoDot: registration/business records). Dot.Files provides common storage, organisation, access control, movement, audit; the owning platform keeps its business logic and domain access decisions. Centralised storage ≠ centralised unrestricted access.

## 3. Strict business and tenant isolation (the most important requirement)
Every business has an isolated file environment; no cross-company access to files, folders, metadata or references without explicit secure authorisation. Ownership context on every file/folder: tenant/business ID; file ID; folder ID; original uploader; current owner; source platform; current platform association; storage location; classification; permissions; timestamps; retention/lifecycle; version info. Reuse InfoDot's business/tenant architecture — no duplicate identities. Enforce isolation across: DB queries, services, APIs, uploads, downloads, previews, search/indexing, navigation, sharing, jobs, queues, transformations, exports, admin interfaces, storage access, temporary links. Server-side authorisation only. Automated proof tests: A cannot view/download/discover/manipulate-IDs/preview/API-retrieve B's data; jobs cannot process under the wrong tenant; old URLs cannot leak. Tenant isolation is a security boundary.

## 4. Business-oriented file and folder experience
A premium enterprise document-management workspace: create folders/subfolders; single/multi/drag-drop upload; rename/move/copy/delete/restore; download files and folder archives; previews; search; filter/sort; properties; activity; permissions; tags/categories; favourites; recent (accessed/modified); shared-with-me. Formats: PDF, DOC(X), XLS(X), PPT(X), CSV, TXT, images, ZIP, common audio/video where appropriate; validate types, configurable size limits, no dangerous types. Optional business folder templates (Company Documents, Administration, Finance, Accounting & Tax, HR, Legal & Compliance, Contracts, Operations, Projects, Sales & Marketing, Customers, Suppliers, Reports, Policies, Archive) — customisable, never forced.

## 5. Cross-platform file and folder movement (defining capability)
Move/copy files between platforms through Dot.Files (Docs→HR, Analytics→Finance, Projects→Docs, Mines→Operations, Emall→Finance, Agents→company folder). Workflow: select in source → source requests movement via Dot.Files → Dot.Files identifies tenant/ownership/source/permissions → validates user authority → identifies destination platform+folder → validates destination permissions and tenant boundaries → user confirms → perform → destination receives reference+metadata → audit → both platforms get status. MOVE: changes association/location, preserves identity/history, updates references, no broken refs, records old+new. COPY: new managed instance/version, preserves original, records relationship, independent destination permissions, never accidentally shares confidential access. Cross-TENANT movement is never ordinary: verify authority in both businesses, explicit confirmation, destination ownership rules, preserve audit history, record identities, no permission carry-over; admin approval where appropriate.

## 6. Track all file activity (authoritative record)
Events: uploaded, downloaded, viewed/previewed, renamed, moved, copied, shared, permission changed, deleted, restored, version created, transferred between platforms, transferred between businesses, access denied, quarantined, retention/deletion actions. Each event (as applicable): event ID, tenant, file, folder, user, source/destination platform and location, type, timestamp, result, metadata, correlation ID, approval info, failure reason. Never log contents, passwords, tokens. Authorised activity-history UI (who/what/which/where-from/where-to/when/outcome) with filters; audit logs protected from modification/deletion; distinguish ordinary activity from security audit records.

## 7. Ownership, permissions, sharing
Granular, understandable permissions: view, preview, download, upload, create folders, edit metadata, rename, move, copy, delete, restore, share, manage permissions, manage retention — configurable at business/folder/file/platform-integration/role levels, inheritance with controlled overrides. Platform-specific access: least privilege per integration (HR no automatic finance access and vice versa); each integration has identifiable permissions and scope. Sharing (if implemented): specific users; same-business members; other businesses via explicit approved transfer/sharing; external parties via secure configurable links (expiry, revocation, optional password, download restrictions where enforceable, access logging, explicit scope). Never permanent public URLs for confidential documents.

## 8. Security architecture
Threat assessment: cross-tenant leakage, IDOR, broken access control, malicious uploads, malware/ransomware, path traversal, file replacement, MIME spoofing, unsafe previews, insecure temp URLs, API abuse, privilege escalation, compromised integrations, job tenant confusion, unauthorised sharing, accidental deletion, credential exposure. Storage: private object storage; encryption in transit and at rest; key management; short-lived authorised URLs; server-side checks before issuing URLs; secure naming/paths; upload validation/sanitisation; limits; malware scan/quarantine where available; safe preview processing; safe archive extraction; integrity verification; versioning and recovery. No sensitive files in public directories; no storage credentials in frontends. Previews are a separate security boundary (no active content; sandbox/convert/isolate; same permissions as downloads). Retention: configurable policies, soft delete, secure permanent deletion, legal hold, exceptions, version retention, recovery; never permanently delete under hold/need without approval.

## 9. Versioning and integrity
Upload new versions; view/compare/restore previous (where permitted); who/when/which platform per version. Checksums or equivalent; movement never silently alters content; record version relationships; avoid unnecessary duplicate physical files where references/versions suffice.

## 10. Search and discovery
Fast tenant-aware search: names, folders, tags, categories, types, source platforms, metadata, indexed content where supported. Filters, sorting, pagination, recents, favourites, platform filters, navigation, suggestions. Content indexing respects tenant boundaries and permissions; no snippets from inaccessible documents. AI search only with proper authorisation, data controls and disclosure.

## 11. Intelligent organisation and AI readiness
Potential: auto-classification, suggested destinations, type recognition, metadata extraction, duplicate detection, related documents, expiry detection, contract/compliance identification, intelligent search, summaries, retention suggestions. AI never changes ownership/permissions/legal status/retention automatically; AI metadata distinguishable from verified; sensitive documents protected during processing; no fake AI functionality.

## 12. Integration architecture and developer experience
Consistent API/integration package: service-to-service auth; platform credentials and scopes; upload; retrieval; reference resolution; folder creation; movement; copying; permission verification; activity events; versions; webhooks/events; idempotency; retries; error reporting. Platforms registered as authorised integrations; no direct storage-backend access. Reusable client package/contract where appropriate. Document auth, endpoints, structures, scopes, errors, rate limits, retries, events, examples; versioned APIs, backwards compatibility. Events: file.uploaded, file.moved, file.copied, file.deleted, file.restored, file.version.created, file.permission.updated, file.transfer.completed, file.transfer.failed — reliable delivery, idempotent, retried, dead-lettered; no fragile synchronous chains.

## 13. UI and design transformation
Exceptional look and feel. Inspect and apply the installed design/UX/content skills; use Laravel Boost; follow the Dot design language where appropriate; no generic templates. Premium enterprise experience; inspiration (not copying): Apple Files, Dropbox, Google Drive, OneDrive, SharePoint, Linear. Principles: minimal, sophisticated, professional, excellent typography, beautiful presentation, intuitive navigation, subtle animation, clear hierarchy, responsive, consistent spacing, accessible, fast, useful empty states, clear loading/errors; avoid generic AI-SaaS patterns. Navigation: My Files, Business Files, Shared With Me, Recent, Favourites, Trash, Activity, Platform Files, Administration. Workspace: breadcrumbs, search, filters, listings, grid/list, sorting, selection, context menus, uploads, bulk actions. Info panel: preview, name/type, size, owner, dates, location, source platform, versions, permissions, activity. Movement UI: destination platform/business/folder selector, move vs copy, access implications, clear explanation before sensitive transfers. Micro-interactions that all work; no decorative non-functional elements.

## 14. Business administration and governance
Admin interface: storage usage, user access, folder permissions, activity review, retention settings, external sharing review, platform integrations, transfer activity, suspicious activity, storage policies. Configurable quotas; display real capacity/used/available/counts/consumption-by-category/largest/recent (actual usage, never fabricated). InfoDot-level support capabilities limited, justified, authorised, audited — never unrestricted access to confidential documents.

## 15. Performance and scalability
Plan for many businesses, millions of files, large folders, concurrency, large previews, high-volume audit, integration traffic, background processing, storage expansion. Indexing, pagination, query optimisation, queues, chunked/resumable uploads, caching, storage abstraction, background processing, efficient delivery, rate limiting. No loading whole folders/histories into memory; one tenant cannot degrade another; realistic measured targets, not invented benchmarks.

## 16. Testing and security verification
Functional: folders/nesting, uploads single/multi, downloads, previews, rename, move, copy, delete, restore, versions, search/filter, permissions, activity, storage usage. Ecosystem: upload from Docs; retrieve from HR; Finance documents; Analytics reports; Mines records; Projects documents; moves between authorised platforms; destination references; activity records; failed transfers and retries — real integrations only, unimplemented ones clearly identified. Security: two independent tenants, multiple roles — cross-tenant file/folder access, ID manipulation, direct URLs, API authorisation, search leakage, preview leakage, job isolation, platform credential misuse, privilege escalation, malicious uploads, MIME spoofing, path traversal, inheritance, revocation, cross-tenant approvals, audit integrity. Automated regression tests for every critical boundary; CI gates green.

## 17. Phases
1 Architecture & security foundation (audit; tenant model; ownership/permission architecture; storage security; integration contracts; preserve list). 2 Core file management (upload/download complete; folders; previews; search; metadata; versioning; permissions). 3 Cross-platform integration (platform registration; scopes; references and movement services; move/copy; events; pilot 1–2 platforms; expand after validation). 4 Audit & governance (activity tracking; audit UIs; administration; retention/recovery). 5 Design & experience (installed skills; full redesign; responsive; empty states; usability). 6 Production hardening (security tests; integration tests; performance; storage recovery; monitoring; deployment; production verification). Never deploy incomplete security foundations to move faster.

## 18. Definition of done
1 isolated environments; 2 clear ownership/policies; 3 no cross-business access; 4 full management for authorised users; 5 secure moves between authorised platforms; 6 distinct correct move/copy; 7 cross-platform activity recorded; 8 cross-tenant transfers explicitly authorised; 9 integrations cannot bypass controls; 10 versions and integrity; 11 search respects boundaries; 12 admin capabilities; 13 tests pass; 14 polished responsive functional UI; 15 storage/backup/recovery verified; 16 integration and admin documentation.

## 19. Final deliverables
Architecture assessment; isolation/security design; database/ownership model; management implementation; integration contract; move/copy implementation; activity/audit system; permission model; storage/recovery; redesigned UI; test coverage; security test results; deployment evidence; platform integration status matrix (per platform: upload? retrieve? move/copy? scopes? activity recorded? production-tested?); outstanding issues. Never mark a platform integrated because an endpoint or client exists.

## 20. The product standard
The digital filing infrastructure businesses rely on daily: one business, one secure file environment, multiple connected platforms, complete visibility and control over every authorised movement. Simple for the user, sophisticated behind. Do the actual implementation — not diagrams, recommendations or mocks. Laravel Boost; installed design skills; preserve working functionality; security foundation first; test every critical workflow. Security, tenant isolation, data integrity and aesthetics are non-negotiable. Production-grade, trusted with the most important documents.
